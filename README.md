# Практическая работа по SQLAlchemy, Alembic и Docker Compose

В репозитории есть FastAPI-сервис для товаров и заказов. Сейчас он хранит данные в памяти. Задача — перенести данные в PostgreSQL и настроить запуск всего проекта одной командой.

## Запуск исходного API

Нужен Python 3.11 или новее. В активированном виртуальном окружении выполни:

```sh
python -m pip install -r requirements.txt
python -m uvicorn main:app --reload
```

Открой [Swagger UI](http://localhost:8000/docs). Там можно создать товар и заказ, а затем посмотреть оба списка. Цены передаются целым числом в копейках.

## Задание

1. **SQLAlchemy и PostgreSQL.** Добавь модели `Product` и `Order` и замени хранение в памяти запросами к БД. Свяжи `orders.product_id` с `products.id` внешним ключом. Подключение передавай через переменную `DATABASE_URL`. Сохрани адреса и форматы ответов существующего API.
2. **Alembic.** Настрой Alembic на метаданные моделей и создай первую миграцию для обеих таблиц. Напиши `upgrade` и `downgrade`. На пустой базе `alembic upgrade head` должен создать схему.
3. **Docker.** Напиши `Dockerfile` для API и добавь `.dockerignore`. Приложение внутри контейнера должно слушать `0.0.0.0:8000`.
4. **Docker Compose.** Добавь `compose.yaml` с API и PostgreSQL. Используй именованный том для данных PostgreSQL и `healthcheck` для проверки готовности БД. Настрой запуск миграций после готовности БД и до старта API. Добавь `.env.example` с примером настроек для локального запуска.

## Как проверить результат

1. Выполни `docker compose up --build` на чистом проекте. После старта открой [Swagger UI](http://localhost:8000/docs).
2. Отправь `POST /products` с телом `{"name":"Чай","price_kopecks":12900}`. Ожидается `201` и идентификатор товара.
3. Отправь `POST /orders` с телом `{"product_id":1,"quantity":2}`, подставив полученный идентификатор. Ожидается `201`. Для отсутствующего товара ожидается `404`, для количества `0` — `422`.
4. Выполни `docker compose down`, затем `docker compose up`. Запросы `GET /products` и `GET /orders` должны вернуть созданные записи.
5. На отдельной тестовой базе проверь, что после `alembic downgrade base` можно снова выполнить `alembic upgrade head`.
